# ohPrimer inventory

ohPrimer (branded "Trellis" in-app) is an 8065-line single-file PWA: a family reading engine welding fast intake (RSVP/parafoveal/scroll/speak modes) to SM-2 spaced repetition. Four screens (Home/profiles, Library, Reader, Review) plus ~10 modals. Intake: EPUB (JSZip, TOC nav+NCX, figure blobs, front-matter skip), PDF (pdf.js with column/footnote heuristics, Tesseract OCR fallback), TXT/MD (table/code/divider heuristics), paste, URL article extraction, Gutenberg (Gutendex), RSS/Atom+podcast feeds (iTunes search, auto-discovery, OPML, conditional GET, auto-download), .ohcourse curriculum import, AI-generated passages, and audio transcription. On-device ML via pinned @xenova/transformers@2.17.2 from esm.sh (?bundle): Whisper-tiny.en (~40MB, ENGLISH-ONLY; sourceLang hardcoded eng_Latn), NLLB-200-distilled-600M (~612MB, 22 langs), SpeechT5+CMU-ARCTIC x-vectors (~200MB, 4 preset "clone" voices), Kokoro-82M (~86MB, ~54 voices). MODEL_SIZES_MB at index.html:6834. All inference forced single-thread WASM (GH Pages lacks COOP/COEP; no WebGPU on v2). A blob-URL module worker (index.html:6913-7089) runs all four tasks with per-task sticky fallback to main thread; worker evictExcept (6924) keeps exactly ONE model resident. Downloads: sticky consent gate with metered-connection warning, cumulative progress + 90s stall watchdog, "cancel" merely abandons the promise (transformers v2 has no AbortSignal) relying on browser-cache range resume. Transcripts persist ONLY after full completion (7807) — no checkpointing; the worker call inherits runInWorker's 120s default timeout, so any real podcast times out, sets sticky worker-off, re-decodes and reruns on the main thread. Whole episodes are buffered in memory (300MB cap) and decoded/resampled to one giant Float32Array. Storage: localStorage "openhearth_primer_v01" (profiles/prefs/feeds/consents); IndexedDB "openhearth_primer_db" v3 with stores books(byProfile,byLastRead), extracts(byProfile,byBook,byNextReview), episodes(byFeed,byGuid,byPublished,byProfile — also holds voice-clone WAVs under clone:* ids); model weights in browser cache; sw.js network-first shell + SWR CDN cache. Cloud sync removed (functions dormant, entry points throw). rebuild/ has 108 passing node tests over 7 ported modules (utils, state, privacy, tokenizer, partial parsers, partial learning/SM-2, comms); reader rendering, UI/modals, feeds UI, the entire ML layer (60-ai), and init/SW have NO module tests — only 11 Playwright behavior tests and 2 visual scripts. Docs: VISION, 7 ADRs, Diátaxis set, v0.1 robustness spec.

## Jank
- **Successful transcripts take ages; UI can freeze during them** — root cause: Worker transcribe inherits runInWorker's 120s default timeout (index.html:7073-7078; call at 7762 passes no timeoutMs). Any real podcast exceeds 2 min on single-thread WASM whisper-tiny (numThreads=1 forced because GH Pages sends no COOP/COEP — 6822-6827; pinned transformers 2.17.2 predates WebGPU), so the worker is killed mid-inference, _workerTranscribeOk goes sticky-false, and the ENTIRE audio is re-decoded and re-transcribed on the main thread (7771-7775) — double work plus a frozen tab. No inference progress is shown either way (only model-file download %). — fix: Pass a duration-scaled or infinite timeout for transcribe (keep the watchdog for load only), stream per-chunk progress/results from the worker, and keep inference off-main permanently; longer-term serve with COOP/COEP or upgrade to transformers v3 for threads/WebGPU.
- **Failed transcripts, especially long episodes on mobile** — root cause: Everything is buffered in RAM end-to-end: fetchBinaryWithProxies accumulates up to 300MB of chunks (7848-7871), then loadAudioTo16k decodeAudioData's the whole file AND renders a full-length 16kHz Float32Array via OfflineAudioContext (7703-7713) — a 3h episode is ~700MB of samples, and the worker path immediately makes another copy (audio.slice() at 7761). iOS Safari's ~1GB tab budget OOMs. The transcript is persisted ONLY after full completion (persistNewBook at 7807) — no checkpointing — so a backgrounded/killed mobile tab loses everything, and enclosure fetches ride flaky public CORS proxies (cors.eu.org/allorigins, 7843). — fix: Chunked decode+transcribe (fixed-size windows fed to Whisper's stride API), checkpoint partial transcript + resume offset in the episodes store per chunk, stream fetch to IDB blob instead of RAM, drop the extra copies.
- **Painful model downloads (owner complaint)** — root cause: Up to 612MB (NLLB) fetched by transformers v2 which exposes no AbortSignal — Cancel (7115-7118) just abandons the promise while bytes keep flowing; resume relies on opaque browser-cache range behavior with no first-class resume UI (README:76, docs/limitations.md). Stall watchdog only fires after 90s of zero progress (7128). Weights live in the evictable browser cache, not the SW cache (sw.js:9-10), so an eviction silently re-triggers the whole download. Kokoro path shows per-file % without MB totals (7562). Everything imports from esm.sh at runtime — a CDN outage bricks all ML. — fix: Own the download: fetch model files with AbortController + Content-Range resume into Cache Storage/OPFS, show real MB progress and a persistent resume card, then point transformers at the local cache (or upgrade to v3 which supports custom cache).
- **Whisper produces garbage for non-English podcasts** — root cause: Model is Xenova/whisper-tiny.en — English-only (6950, 7735) — and addAudioFile hardcodes sourceLang "eng_Latn" (7801-7802), so translation of transcripts also assumes English source. No model-size/language choice. — fix: Offer multilingual whisper-tiny/base variants with a language picker; store detected language on the book record.
- **Switching between Speak/Translate/Transcribe features is slow every time** — root cause: Worker evictExcept (6924-6930) disposes every model except the one in use, and the main thread mirrors this (7113-7114, 7330-7333) for iOS's ~1GB budget — so each feature switch pays full ONNX session re-init (weights come from cache but session build is seconds-to-minutes single-threaded). Sticky _worker*Ok flags (7155,7444,7579,7743) also mean one transient worker failure demotes that feature to main-thread for the whole session. — fix: Keep memory budget but make eviction platform-aware (desktop can hold 2+ models), persist session-init state where possible, and let sticky flags reset after a cooldown or on explicit retry.
- **Translation strip stalls on first use and per-block thereafter** — root cause: First block triggers the full ~612MB NLLB download inline (renderTranslationStrip → translateViaWorkerOrMain → loadNllb, 7195-7258); every new block is a separate on-demand forward pass with no prefetch of upcoming blocks; cache is per-book per-language stored inside the ever-rewritten book record. — fix: Prefetch next N blocks in the worker while reading; consider a smaller default model tier.
- **Voice-clone synthesis takes 5-15 minutes and blocks the feature** — root cause: readCurrentDocInVoice synthesizes the ENTIRE document up front through SpeechT5 sentence-chunks before any audio plays (7483-7518); settings hint itself admits 5-15 min for a 30-min episode (index.html:1077). Cache is all-or-nothing per (book,preset). — fix: Stream playback as chunks complete (queue WAV pieces into MediaSource/sequential Audio) and checkpoint partial synthesis.
- **Feed/article/episode fetches intermittently fail or rate-limit** — root cause: Dependence on three public CORS proxies (cors.eu.org, allorigins, codetabs — 3524, 7843) for any host without CORS headers; proxies strip conditional-GET headers (3615) and rate-limit; acknowledged in README:75. — fix: Optional self-hosted proxy setting, or native-app path; batch feed refreshes through a single proxy session.
- **Position autosave rewrites megabytes; storage churn** — root cause: Book records store the full parsed blocks + figureBlobs + translations in one IDB record; saveCurrentPosition re-reads and rewrites the whole record whenever position changes (3319-3328, comment admits a positions-store migration was deliberately skipped). — fix: In the rebuild, split position/lastReadAt (and translations) into a small sibling store keyed by bookId.
- **Rebuild is half-done; the riskiest code has no unit tests** — root cause: rebuild/ has 108 tests but only for utils/state/privacy/tokenizer/partial-parsers/SM-2/comms (manifest.json scripts vs scriptsTodo). Reader modes (30-reader), UI/modals (35-ui), feeds UI (45-content), the ENTIRE ML layer (60-ai), and init/SW (90-init) exist only in index.html with zero module tests — exactly the layer the owner's complaints live in. EPUB/PDF parsers also unported (deferred H1/H8). — fix: Port 60-ai next with the worker protocol behind a testable seam (mock pipeline), since that's where downloads/transcription bugs concentrate; keep porting method from rebuild/README (verbatim extraction, issue-ID regression tests).
- **Episodes store fields never populated; per-profile leakage** — root cause: episodes store declares byGuid/byProfile indexes (1287-1290) but records written by audDl/autoDownloadQueue/putCachedClone never set guid or profileIdx — cached audio and voice clones are global across profiles, and profile deletion (5260-1283) cleans books+extracts but leaves episode blobs orphaned. — fix: Stamp profileIdx/guid on write; include episodes in profile-delete cascade and in the (orphaned) storage-panel bucket.
