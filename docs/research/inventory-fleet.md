# Fleet precedent inventory (for reuse by a web-stack app)

## 1. Parlour — single-file PWA + WebView-shell APK — REUSABLE, the fleet's proven web-stack pattern

**PWA** (`/mnt/tera/working/programming/OpenHearth/Parlour/`):
- Pure-logic game modules in `games/*.mjs` (no DOM/network/timers), tested with `node:test` (~276 tests, zero runtime deps). `build.mjs` finds every `export`, strips the keyword, wraps each file in a namespaced IIFE (`const HEXCODLE = (function(){…})();`) and inlines it at the `/*__GAMES__*/` marker in `index.template.html` → generated `index.html` (never hand-edited) (`Parlour/build.mjs`, `Parlour/AGENTS.md`).
- Offline: `sw.js` app-shell cache (`parlour-v1`), stale-while-revalidate over `['./', 'index.html', 'manifest.webmanifest', 'icon.svg']` (`Parlour/sw.js`).
- Deploy: the repo's static files on `master` ARE the site at `levitatingflyfisher.github.io/Parlour/`; workflow is `npm test && npm run build`, commit source + regenerated `index.html` together. No CI deploy automation in-repo, deliberately (`Parlour/docs/how-to/ship-pwa-and-apk.md`).
- Non-negotiables enforced by policy/tests: zero network calls after load, no accounts/ads/tracking, game logic stays pure (`Parlour/AGENTS.md`).

**Shell APK** (`/mnt/tera/working/programming/OpenHearth/ParlourShell/` — a separate, unpublished Flutter repo, forked from the Trellis shell):
- One file, `lib/main.dart`: `webview_flutter` `WebViewController` loading the **live** PWA URL (`https://levitatingflyfisher.github.io/Parlour/`), JS unrestricted, background set to the PWA theme color, `PopScope` walks WebView history before exiting. The PWA's own service worker gives the APK offline play; updates propagate on next shell load with no APK rebuild (`ParlourShell/lib/main.dart`).
- Signing: **debug keystore** in the release build (`signingConfig = signingConfigs.getByName("debug")`), `applicationId com.openhearth.parlour` (namespace still `com.openhearth.trellis` from the fork) (`ParlourShell/android/app/build.gradle.kts`). Distributed as a GitHub Release asset `Parlour.apk` via `releases/latest/download/` (`Parlour/docs/how-to/ship-pwa-and-apk.md`).

## 2. DomovoiDiscernment (`OpenHearth/DomovoiDiscernment/`)

**The one resumable-download engine** (`lib/src/transfer/resumable_transfer.dart`) — PATTERN reusable, CODE not (Dart+dio, and the doc comment says "native builds only; web surfaces keep their own inert variants"):
- **Not content-addressed.** Resume = HTTP `Range: bytes=N-` from the `.part` file length; a 416 (partial > resource) deletes and restarts; a 200-instead-of-206 on resume also restarts (appending onto stale bytes would corrupt).
- **Integrity is the caller's `promote` callback**, not the engine's: completion IS the caller's atomic `.part → final` rename (and optional sha check/gunzip) inside `promote` — "never a size judgment". Error anywhere (transfer or promote) is the future's error.
- **Progress contract**: `(receivedBytes, totalBytes?)`, offset by `resumeFrom` so the caller tracks the whole file; `total` null/-1 when the server omits Content-Length. Stream variant is **cold** (nothing hits the wire until subscribed), one listener, `onOutcome` fires exactly once before close with `completed | cancelled` — cancel keeps the partial and `promote` never runs. A JS port is straightforward (fetch + Range + IndexedDB/OPFS), but you rewrite it.

**Brain seam** (`lib/src/brain.dart`) — trivially portable interface: `abstract class Brain { Future<String> complete(String prompt); }` + `AskException(message, {cause})` where message is user-displayable, cause stays in logs. On-device / stove / BYOK-cloud implementations all hide behind it; callers never know which.

**Stove protocol** (`docs/reference/stove-protocol.md`, `lib/src/keys.dart`, `lib/src/stove/`):
- Plain HTTP on LAN, port **4663** ("HOME" on a keypad), server binds `InternetAddress.anyIPv4` (`stove_server.dart:68`).
- Key: BIP39 phrase → standard 512-bit seed (PBKDF2-HMAC-SHA512, 2048 iters, salt "mnemonic") → HKDF-SHA256, no salt, info `openhearth.domovoi.stove.v1` (FROZEN) → 32-byte frame key. **The secret IS the pairing** — no key crosses the wire (`keys.dart`).
- Exchange: `GET /stove/status` (cleartext probe) → `GET /stove/challenge` (16 random bytes b64, 60s TTL, single-use, 256 max outstanding → 503) → `POST /stove/ask` with cleartext `x-stove-challenge` header + AEAD frame body. Frame = `nonce(12) ‖ ciphertext ‖ mac(16)`, ChaCha20-Poly1305 IETF, AAD = `"domovoi-stove/v1" | endpoint | challenge` (endpoint ∈ {ask, answer}) — no replay across endpoints/versions/asks. Every failure is a constant-shaped `403 refused`; 1 MiB ask cap; 30s body deadline.
- **JS feasibility**: the cipher is the small problem — ChaCha20-Poly1305 is absent from WebCrypto but solved by libsodium.js (`crypto_aead_chacha20poly1305_ietf_*`) or the zero-dep pure-JS `@noble/ciphers`; HKDF-SHA256 and PBKDF2-HMAC-SHA512 are **native WebCrypto** `deriveBits`. A **Node.js** stove client is fully feasible today. A **browser** client is NOT, for two non-crypto reasons: (a) the Dart server emits no `Access-Control-*` headers and the custom `x-stove-challenge` header + octet-stream POST forces a CORS preflight (`OPTIONS`) the server would 404 — grep of `stove_server.dart` finds no CORS handling; (b) an https-served PWA cannot fetch `http://` LAN addresses (mixed content / Private Network Access). A browser client needs server-side CORS + a serving-context answer first.

## 3. sanctuaryAuth — OHBK wire format — FORMAT fully portable to JS; no yellow paper exists

Spec-by-code in `/mnt/tera/working/programming/OpenHearth/packages/sanctuary_auth_core/` (the `OpenHearth/sanctuaryAuth/` dir holds only PRD/spec markdown; `docs/` has no yellow paper — the authoritative wire format is `lib/src/backup/ghost_backup.dart`):
- **OHBK v2**: `[4B magic "OHBK"][1B version 0x02][1B suite 0x01=ChaCha20-Poly1305 IETF][12B nonce][16B Poly1305 MAC][N ciphertext]`. AAD = `header ‖ utf8(context)`; default context `'ghost-backup/v1'`, distinct labels per purpose block cross-context blob substitution. v1 (no AAD) still importable, never emitted. Min blob 34 B, max 10 MB both directions (fail closed at export).
- **Key derivation** (`lib/src/crypto/key_derivation.dart`): 64-byte BIP39 seed → HKDF-SHA256 (no salt, 32-byte out) with frozen info strings; per-app isolation via `appDomain` → `openhearth.<appDomain>.<purpose>.v1` (`^[a-z0-9]+$`, reserved-word guard so `appDomain='sync'` can't collide with the frozen legacy `openhearth.sync.encryption.v1`). Five keys: masterEncryptionKey, syncKey, authKey, recoveryKey, syncChannelId. Plus `deriveKey(secret, domain)` for arbitrary non-BIP39 secrets.
- **JS feasibility: same verdict as the stove** — byte layout is trivial `DataView` work; HKDF/PBKDF2 native in WebCrypto; only ChaCha20-Poly1305 needs libsodium.js or @noble/ciphers. Nothing here needs a network, so no CORS problem — an OHBK reader/writer in the browser is entirely feasible.

## 4. ohStyle — tokens — DIRECTLY web-consumable

`/mnt/tera/working/programming/OpenHearth/ohStyle/openhearth_tokens/tokens.css` (with a `tokens.ts` twin) ships CSS custom properties: Hearth terracotta ramp (primary `--oh-hearth-500: #A85040`), Linen warm neutrals (bg `#FBF8F4`, card `#F5EFE6`, text `#2C1810`), Sage success, Slate info, amber/red accents; hearth-dark + neutral "night" surface palettes; spacing 4/8/16/24/40/64; radii 4–16 + full; type `--oh-font-heading: 'Lora', Georgia, serif` / `--oh-font-ui: 'Nunito', system-ui`; warm linen-tinted elevation shadows; motion durations 80–400 ms; semantic tokens with a `prefers-color-scheme: dark` block. Flutter twin is `openhearth_design` (`OhColors`), kept in sync by C1. Known trap: Lora+Nunito lack `≤`/`≥` glyphs (the C7 origin story).

## 5. Landing deploy model — REUSABLE

`/mnt/tera/working/programming/OpenHearth/_ohsite_build/` is a git checkout of **`levitatingflyfisher/levitatingflyfisher.github.io`** (user-pages repo, `master` served from root) — a single 244-line static `index.html`, self-hosted Fraunces+Nunito (`fonts/fonts.css`; explicit "no Google Fonts egress from the front door" comment), inline light/dark palette. Cards render client-side from a JS `APPS` array: each entry = `{name, icon (inline SVG), kind, desc, c1/c2, pwa, apk?, desktopBuilds?, soon?}`. Buttons are platform-typed by color: copper `btn-web` → PWA, pine `btn-apk` → `github.com/<owner>/<Repo>/releases/latest/download/<App>.apk`, slate `btn-desktop` → glean (desktop-only detection via `matchMedia(min-width:900px) and (pointer:fine)` + UA OS sniff), `btn-na` for unavailable. **Trellis card today** (lines 170–175): trellis-lattice SVG in `#C47B6A`/`#A85040`, kind "Spaced repetition", `pwa: …github.io/Trellis/`, `apk: …/Trellis/releases/latest/download/Trellis.apk`. Adding a web app = one `APPS` entry + push to master.

## 6. oh_fleet_conformance C1–C7 — Flutter/Dart-only; VALUES portable, code not

`/mnt/tera/working/programming/OpenHearth/packages/oh_fleet_conformance/` runs inside `flutter_test` via one `runFleetConformance(FleetAppConfig(...))` file (README). Checks: **C1** style single-source (canonical `openhearth_design` by sibling path, no vendored forks/retyped hex); **C2** backup retention (sanctuary_backup_ui ≥0.2.0, shared `BackupEnvelope` serializer); **C3** size budgets (`budgets.json` vs gzipped `main.dart.js` + arm64 APK, measure–budget–ratchet); **C4** exact Android `<uses-permission>` surface both directions **incl. the release merged manifest** — the no-INTERNET / zero-permission claims are tests, not promises; **C5** a11y sweep at 320 dp × 3.0 text scale incl. opened dialogs; **C6** harness canon (flutter_test_config, analysis_options, CI pinning the fleet Flutter version); **C7** fonts (opt-in via `FleetAppConfig.withBundledFonts`, absent from `defaultChecks`) — every printed character must exist in the bundled font cmaps, with emoji + never-drawn parser character-classes exempt, and written to fail-on-nothing-found (`lib/src/checks/fonts.dart`, `lib/src/fleet_conformance.dart:32,94`). A web-stack app can't run any of it directly but should re-pin the same values: token single-source, size budgets, no-network-as-a-test, 320dp/3× a11y, glyph coverage.
